# echo · 需求文档

> 项目名 `echo`（生活的回声）为临时占位，可随时替换。
> 状态：🚧 需求评审中（待贰玖确认交互与功能）
> 最后更新：2026-05-29

## 1. 项目定位

echo 是一个**给个人使用的 Android 语音生活记录 App**。

它在后台持续监听，听到有人说话就自动录下来，每天自动把当天的语音整理成结构化的日记 / 待办 / 灵感 / 时间线。核心价值是**零摩擦、不遗漏**——不需要用户记得"打开录音"，重要的对话和想法不会因为忘记按按钮而丢失。

一句话：**一个一直帮你听着、每天帮你整理的语音黑匣子。**

## 2. 目标用户

只有一个用户：贰玖本人。

这意味着：
- 不需要多用户、账号体系、权限隔离。
- 可以接受"手动配置一次电池白名单"这类一次性成本。
- 设计完全围绕单人长期使用的习惯优化，不做通用化妥协。

## 3. 三条核心理念（一切设计的依据）

| 理念 | 含义 | 推导出的约束 |
|------|------|-------------|
| **零摩擦** | 不靠用户主动触发 | 后台常驻 + 人声自动激活录音 |
| **不遗漏** | 重要内容不能因忘记操作而丢 | 环形预录缓冲，不丢句子开头 |
| **每日沉淀** | 原始语音不是终点，整理结果才是 | 每天自动转写 + 大模型整理 |

## 4. 功能需求（按"能力链"拆解）

录音到整理是一条单向流水线，逐环拆解：

### 4.1 听 · 持续监听
- App 启动后开一个**前台 Service** 常驻运行，麦克风持续采样。
- 带一个**常驻通知**（Android 强制要求），通知上提供一键暂停。
- 录音格式：16kHz 单声道，Opus 或 AAC 编码（省空间）。

### 4.2 判 · 人声自动激活（VAD）
- 本地做 **VAD（语音活动检测）**：只有判定"有人在说话"才落盘，静音直接丢弃。
- **环形预录缓冲**：内存里滚动缓存最近 1~2 秒音频，一旦 VAD 触发，把缓冲区内容一起补进来——**保证不丢句子开头**。
- 目的：省存储、省转写成本、去掉无意义噪音，而不是省电（麦克风为了监听必须常开）。

### 4.3 存 · 本地缓存 + 上传队列
- 有效语音片段先存本地，进入**上传队列**。
- 断网不丢：联网后自动补传。
- 已成功转写的本地音频按策略清理（保留 N 天 / 上限多少 GB，待定）。

### 4.4 传 · 上传转写
- 仅上传"确实有人说话"的片段到云端。
- 采用**批量转写**（录音文件识别），不用实时流式——更便宜，且每日整理不需要实时。

### 4.5 写 · 转文字
- 云端中文 ASR 把音频转成文字，带**时间戳**。

### 4.6 分 · 说话人分离 + 声纹认领
分两层，第一层成熟、第二层渐进：

**第一层 · 说话人分离（diarization）**
- 转写时同步把片段切成"说话人 A / B / C"，只标编号，不知道是谁。
- 这一层基本随转写免费搭车，是必做项。

**第二层 · 声纹认领（渐进式，echo 的特色）**
- 用户在 App 里看到 Speaker B，点一下标注成"老婆 / 张三 / 我"。
- 系统把这段已确认音频**提取声纹存进本地声纹库**，以后再遇到同一声音**自动贴名**。
- **一次性投入**：每个常对话的人第一次出现时标一次，之后系统自己认。
- 规则：**先编号 → 标注后命名 → 之后自动**；认不出就保留 Speaker N，**宁可留编号也不贴错名**。
- 第一个该认领的一定是**贰玖自己**——把"我说的"和"别人说的"分开，是整理日记最关键的一刀。

### 4.7 整 · 每日整理
- 每天定时（如凌晨）跑一次，把当天所有转写文本 + 说话人信息喂给大模型。
- 产出结构化结果，至少包含：
  - **每日日记**：用自然语言复述今天发生了什么。
  - **待办**：从对话里提炼出的行动项 / 承诺。
  - **灵感**：值得留住的想法。
  - **时间线**：几点左右、和谁、聊了什么。
- 结果存成**每日一份**（Markdown 或结构化数据）。

### 4.8 看 · 查看结果
- App 内按"天"浏览整理结果。
- 能进到某天看：整理摘要 + 原始转写（带说话人和时间戳）。
- 在转写视图里能完成"声纹认领"的标注动作。

## 5. 交互设计（极简优先）

整个 App 围绕一个事实设计：**它主要在后台自己干活，用户大部分时间不需要碰它。**

所以交互极度收敛，只有三类动作：

1. **开 / 关 / 暂停录音**——一个主开关，外加通知栏快捷暂停。
2. **浏览每天的整理结果**——按天翻。
3. **认领说话人**——看到陌生编号点一下贴名。

除此之外不做任何多余功能。没有设置迷宫、没有花哨仪表盘、没有社交分享。

### 界面结构（极简，3 个主界面）

```
①「今天」主页（App 打开第一眼）
   ├─ 一个大的录音状态开关（正在听 / 已暂停）
   ├─ 今日简单状态：已记录 N 段、时长约 X
   └─ 入口：查看今天的整理结果

②「历史」按天列表
   └─ 点某天 → 当天详情

③ 当天详情
   ├─ 上半：AI 整理结果（日记 / 待办 / 灵感 / 时间线）
   └─ 下半：原始转写（带说话人、时间戳，可点说话人认领）
```

底部最多两个 Tab：**今天 / 历史**。设置项极少，能塞通知栏和长按就不单开页面。

## 6. 极简设计原则（同时服务"好用"和"AI 好实现"）

贰玖明确要求 UI **极简、极简、极简**，原因有二：① 方便操作；② 项目用 coding agent 写代码，AI 当前审美能力弱。两条诉求指向同一套约束：

- **把审美决策在文档里前置定死**，让 coding agent 只做"翻译"，不做"创造"。
- **全用 Material Design 3 原生组件 + 默认样式**，不自定义绘制、不写复杂 Canvas。
- **单列布局**，从上到下排，不做多栏 / 不规则网格。
- **零或极少动画**，最多用系统默认过渡。
- **配色用 M3 动态取色或一套固定的中性色**，不手调渐变和阴影。
- **信息密度低**，大量留白，一屏只讲一件事。

> 这条原则会在下一份《UI 设计文档》里展开成可执行的视觉规格（间距、字号、组件清单、每屏布局），供 UI 出图。

## 7. 技术约束与风险（必须认下来）

| 风险 | 说明 | 应对 |
|------|------|------|
| **厂商杀后台** | 国产 ROM（小米/华为/OPPO/vivo）杀后台凶，是"能否跑满一天"的命门 | 引导用户手动加电池白名单 + 锁后台；前台 Service + 常驻通知 |
| **隐私与法律** | 连续环境录音会录到他人对话，云端上传更敏感 | 贰玖自担；提供随手暂停；后续可考虑敏感场景手动停 |
| **声纹准确率** | 远场、嘈杂、多人抢话时会认错/认不出 | 只服务少数常对话的人；认不出留编号；支持事后手改 |
| **转写成本** | 一天有效语音可能 1~2 小时 | VAD 砍掉静音；批量转写；月成本预期几十元量级 |
| **平台限制** | iOS 不支持后台常驻录音 | 本项目**只做 Android** |

## 8. 技术选型建议（详见 design.md）

- **客户端**：Android 原生 Kotlin（后台录音深度依赖系统能力，Flutter 坑多）。
- **VAD**：端上轻量方案（Silero VAD / WebRTC VAD）。
- **ASR + 说话人分离**：云端中文批量转写（火山引擎 / 阿里云 / 腾讯云，自带 diarization）。
- **声纹**：端上声纹特征提取 + 本地声纹库比对。
- **每日整理**：大模型（贰玖已有 Claude）。

## 9. MVP 路径（分三步验证）

不一次做全套，每步独立可用、各验证一个最大风险：

1. **第一版 · 验习惯**：后台常驻录音 + VAD 自动落盘 + 本地存音频，先不上云。跑两天，确认愿意一直开、电量存储扛得住。
2. **第二版 · 验价值**：接云端批量转写 + 每日大模型整理，结果存每日 Markdown。确认 AI 整理出的东西真的有用。
3. **第三版 · 顺手**：说话人分离 + 声纹认领 + 查看界面 + 断网补传等体验。

## 10. 明确不做的事（划清边界）

- ❌ 不做 iOS。
- ❌ 不做多用户 / 账号体系。
- ❌ 不做实时流式转写。
- ❌ 不做"自动认出陌生人"。
- ❌ 不做社交 / 分享 / 云同步多端。
- ❌ UI 不做花哨动效、自定义绘制、复杂仪表盘。

## 已确认的决策（2026-05-29 贰玖拍板）
